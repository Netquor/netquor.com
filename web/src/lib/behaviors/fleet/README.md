# behaviors/fleet

The port of `fleet/site.js` (the price calculator and the free-trial form) and `fleet/pricing.js` (the pack and term math) to Svelte 5 and TypeScript. `/fleet.html` no longer loads either legacy script. The page component creates one model, shares it by context, and starts it after hydration; the server-rendered markup is the complete legacy markup (cards show a dash, nothing hidden), so the page reads correctly without JavaScript and hydrates to the same DOM.

Wiring: `src/routes/(fleet)/fleet.html/+page.svelte` calls `provideFleetModel(createFleetModel({ prices: fleetPricesFrom(data.prices) }))`, `$effect(() => model.setPrices(...))` and `onMount(() => model.mount())` (the returned function is the cleanup). `src/lib/pages/fleet/Calc.svelte`, `LeadForm.svelte` and `Dedicated.svelte` (the "Add it to my estimate" link) call `useFleetModel()` and bind the markup to its stores.

## Modules

| Module | Exports |
| --- | --- |
| `pricing.ts` | `createPricing(prices: FleetPrices)` returns `{ quote, bill, dedicatedCost, price, lifetimePrice, compare }`, the legacy functions with identical output at the seed prices. Also `countDevices`, `off` (round half up on integer cents, BigInt; throws on a non-integer), `volumeBps`, and the constants `PACK` (10), `ANNUAL_MONTHS_PAID` (10), `MAX_DEVICES` (100000), `VOLUME_TIERS` (1 pack 5%, 2 10%, 5 15%, 10 20%, 25 25%), `PACKS_ONLY`, `LIFETIME_YEARS`. No price is typed here. |
| `prices.ts` | `fleetPricesFrom(prices)` reads `fleet.mac.month`, `fleet.mobile.month`, `fleet.{mac,mobile}.year`, `fleet.{mac,mobile}.lifetime`, `fleet.dedicated.{setup,year,month}` from the price snapshot (seed fallback for a missing key); `samePrices`; `FLEET_PRICE_KEYS`. The annual and lifetime license prices now come from their own keys (legacy computed them as 10 and 30 times the monthly price; at the seed they are equal). |
| `calculator.ts` | `renderQuote(comparison, term)` returns the view (three cards with `main`, `sub`, `tag`; `verdict`; `breakdown` lines; `error`) using the legacy strings; `money` (en-US, two decimals), `countOf`, `sliderFor` (the slider follows a number box, held at 500), `initialView` (the server view: a dash and a non-breaking space), `TERMS`, `SLIDER_MAX`, `DEBOUNCE_MS` (120), `ERROR_TEXT`. |
| `form.ts` | `validateLead` (name, then email against `^[^\s@]+@[^\s@]+\.[^\s@]{2,}$`), `mailtoUrl` (`mailto:hello@netquor.com?subject=Netquor%20Fleet%20free%20trial&body=...`, body lines joined by a newline), `statusClass` (`"status " + kind`), `submitLead(values, { say, busy, navigate })` which runs the legacy order: validate, disable the button, `Sending...`, navigate, `Opening your email app...`, enable the button; a throwing navigation becomes a `bad` status. The form posts nowhere (no `/api/lead`, no network request); the honeypot field `website` is not read. |
| `model.ts` | `createFleetModel({ prices, timers?, navigate? })` returns stores `calc` (number and slider values as strings, `dedicated`, `term`, `live`, `view`), `form` (macs, ios, term, dedicated, `touched`) and `status`, and the actions `mount`, `setPrices`, `numberInput`, `rangeInput`, `setDedicated`, `addDedicated`, `selectTerm`, `formInput`, `submit`. Behavior: a number or slider input refreshes after a 120 ms debounce (a newer input replaces the pending one); the checkbox and "Add it to my estimate" refresh at once; a plan click re-renders from the last quote (or computes one); until the visitor edits the form's macs or ios field the calculator mirrors its counts into them, and always writes the plan and dedicated flag; a computation that throws only sets the error text; a sequence number drops stale results; `mount()` returns the cleanup that cancels a pending refresh. |
| `context.ts` | `provideFleetModel(model)`, `useFleetModel()` (a section rendered alone gets a private model). |

DOM contract kept from the legacy script: ids (`calc-mac`, `calc-mac-r`, `calc-ios`, `calc-ios-r`, `calc-dedicated`, `term-*`, `*-main`, `*-sub`, `*-tag`, `verdict`, `breakdown`, `calc-error`, `lead-form`, `lead-status`), the `on` class and `aria-pressed` on the plan buttons, `hidden` on an empty tag (set only once the calculator runs), `aria-live="polite"` on `#verdict` and `#breakdown`, `role="status"` on `#calc-error` and `#lead-status`, `data-touched="1"` on the form, `input` events (not passive-relevant), `change` on the checkbox, `click` on the plan buttons.

## Tests

`pricing.diff.test.ts` loads the legacy `fleet/pricing.js` in a `node:vm` sandbox and compares `compare` over 784 input combinations (and `price`, `lifetimePrice`, `bill`, `quote`, `dedicatedCost` over more) with the port at the seed prices. `site.diff.test.ts` runs the legacy `fleet/site.js` against a hand-written fake DOM next to the model and compares cards, tags, verdict, breakdown, error, inputs, form fields and the submit sequence after each of 400+ step combinations. The rest are unit tests of each module and of the server-rendered markup (`page.test.ts`). The real browser check is `bun run e2e fleet` (scenarios `fleet-calc`, `fleet-form`, plus `nudge-fleet` and `analytics-fleet`).
